## Classic (BDCFF / C64) — Best Practice der Remakes

Amöbe ist **kein** Pathfinder. Pro Scan-Zelle (in-place):

1. **Übergröße letzte Frame** (≥200 Zellen bzw. ~22,7 % der Cave) → diese Zelle wird **Fels** (ruhend).
2. Sonst **Ersticken letzte Frame** (keine Amöbe konnte wachsen) → Zelle wird **Diamant** (ruhend).
3. Sonst: merken, ob *diese* Zelle orthogonal in `space`/`dirt` wachsen *könnte* (Flag fürs Frame).
4. Sonst: **Zufall** — mit p≈3 % (slow) bzw. 25 % (nach Slow-Growth-Zeit) eine der 4 Richtungen wählen; wenn Ziel `space`/`dirt` → neue Amöbe dort (erst nächstes Frame wachstumsfähig).

Globaler Frame-State: `countLastFrame`, `suffocatedLastFrame`, `canGrowThisFrame`, Slow-Timer.

Weitere Classic-Details:

- Firefly/Butterfly **explodieren** bei orthogonalem Kontakt mit Amöbe.
- Amöbe ist **nicht rounded**, nicht impact-explosive; Explosionen **fressen** sie.
- Spieler-Kontakt → Tod (wie Gegner).
- C64-RNG + Scan-Order erzeugen Level-„Charakter“; BD1 hat Extra-Quirks (Magic-Wall-Scan vs. Amöbenzählung).

## Konflikt mit unserem Produkt

[GAMEPLAY](../../GAMEPLAY.md) / ADR: **kein Zufall** bei Physik/Gegnern — Replays und Golden-Tests brauchen Determinismus.

Classic-Amöbe **ist** RNG-getrieben. Remakes, die originalnah bleiben, portieren den C64-PRNG. Wir sollten das **nicht** heimlich einbauen.

## Empfohlene Produktlinie (Deterministisch, classic-feel)

Behalte die **Zustandsmechanik** (Lag-1 Ersticken/Übergröße, Wachstum in empty/dirt, Kontakt-Explosion, Spielertod), ersetze RNG durch feste Intents:

| Classic | Unser Vorschlag |
| --- | --- |
| Jede Zelle würfelt Wachstum | Pro Tick höchstens **N** Wachstums-Schritte (Levelregel, Default 1) |
| Zufallsrichtung | Feste Kandidatenordnung: **N, W, O, S** (oder Level-Parameter); erste freie Zelle gewinnt |
| Welche Amöbe wächst | Scan oben→unten, links→rechts; erste wachstumsfähige Zelle; neu gewachsene erst **nächster** Tick |
| p 3 %/25 % | Stattdessen **Slow-Phase**: alle `k` Ticks ein Versuch; nach `amoebaSlowGrowthTicks` alle `kFast` Ticks (Default k=8, kFast=2 bei 10 Hz) |
| Threshold 200 | `amoebaMaxCells` Levelregel; Default `max(20, floor(width*height*0.227))` |
| Suffocate | Wie Classic: wenn **gesamte** Population keinen Orthogonal-Schritt zu empty/dirt hat → nächster Tick alle → Diamanten |
| Too big | Count ≥ max → nächster Tick alle → Felsen |

Das bleibt golden-testbar und level-designbar, ohne PRNG.

### Alternative (nur wenn gewünscht)

Seeded C64-kompatibler PRNG im `CaveState` (Replay-stabil). Mehr Originalnähe, mehr Test-/Content-Komplexität. **Nicht Default.**

## Tick-Einordnung (ADR)

Nach Gegner-Phase (oder vor): **Amöbe-Phase** mit simultanen Intents aus Snapshot:

1. Zählen / `canGrowAny` aus Snapshot.
2. Wenn `tooBigLast` → alle Amöben → Fels-Intents.
3. Else if `suffocatedLast` → alle → Diamant-Intents.
4. Else → bis zu N Grow-Intents (Claim auf Zielzellen; Konflikt: früher Scan gewinnt).
5. Flags für **nächsten** Tick setzen (`countThis`, `suffocatedThis = !canGrowAny`).
6. Explosion-Queue drain danach (Falls Grow auf… nein; Kontakt Fliege/Amöbe eher in Enemy- oder eigener Check-Phase).

Fliege↔Amöbe: analog Classic in Enemy-Intent **oder** nach beiden Phasen Nachbarschaft prüfen — Empfehlung: im **Enemy-Intent** vor Bewegung (wie Jake Gordon: explode if adjacent amoeba).

## Abnahme (skizze)

- Wächst nur in empty/dirt, deterministische Richtung
- Eingeschlossen → Diamanten (1-Tick-Lag)
- ≥ max → Felsen (1-Tick-Lag)
- Firefly berührt Amöbe → Explosion
- Spieler berührt → Tod
- Digest stabil; Demo 036
