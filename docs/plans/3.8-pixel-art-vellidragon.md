# Plan 3.8: Pixel-Art-Theme (Vellidragon)

Status: Vertrag geklärt — bereit für ADR/Assets (Umsetzung noch nicht gestartet)
Datum: 2026-08-03
Pack: [Sokoban Clone Tiles](https://opengameart.org/content/sokoban-clone-tiles) (Vellidragon / Tammy Spahn, CC0)

## Ziel

Retro-Pixel-Brett als optionales Theme, ohne den Vektorvertrag aus
[ADR 0003](../adr/0003-resolution-independent-board-scaling.md) zu brechen.

## Vertrag (fest)

| Punkt | Entscheidung |
|--------|----------------|
| Default | `theme.standard` bleibt Default (Vektor, ADR 0003) |
| Neu | `theme.retro` (opt-in; Settings-Picker erscheint wegen >1 Theme) |
| Blick | **bird’s-eye**, nicht 3D-Perspektive aus dem Pack |
| Basis | **32×32** px-Texturen; Skala in **Points** (`baseTilePoints = 32`) |
| Retina | 32 pt-Tile + 32 px-Textur auf 2× → 2×2 physische Pixel/Texel; kein separates `@2x`-Asset nötig |
| Schema | **V1 additiv**: optionales `rendering`; fehlend = heutiges Vektor-Verhalten |
| Fehlende/kaputte Textur | Theme ungültig → **pro bekannter ID** Fallback auf Built-in-Standard (Catalog nicht hart failen) |
| Entity-Inset | im Pixel-Profil **0** (volle `tileSize × tileSize`); Vektor behält ~15 % Inset |
| UI-Tokens | Retro-Theme behält eigene HUD-Farben (an Pack angelehnt möglich) |
| Feedback-Symbole (×/✓) | bleiben als Overlay auf `effectLayer` |
| Brett-Symbole / Strokes | im Pixel-Profil aus; Zustände über Texturen/Overlay |
| Lizenz | wie Audio: `THIRD_PARTY_NOTICES.md` + SHA + lokale CC0-Kopie |

## Architektur

```text
theme.retro.json ──► ThemeCatalogLoader ──► VisualTheme
        │                                      │
        │                                      ├─► SokobanBoardScene
        │                                      └─► GridGeometry
Textures/vellidragon/*.png ───────────────────► SokobanBoardScene

GridGeometry:
  vectorContinuous → stufenlose tileSize (ADR 0003)
  pixelInteger     → floor(continuous / baseTilePoints) * baseTilePoints
                     (Mindestmaß / Untermaß: siehe Scale-Paket + Playtest-Gate)
```

Profil steuert nur Darstellung und `tileSize`-Formel. Kein GameCore-Impact.
Branches immer über `rendering.profile`, nie über hardcodierte `themeID`.

## Arbeitspakete

### 1. ADR 0004 – Pixel-Rendering-Profil

- `vectorContinuous` = heutiges Verhalten (ADR 0003).
- `pixelInteger` = ganzzahlige Vielfache von `baseTilePoints`, `.nearest`-Filter,
  Letterbox wächst bewusst.
- `GridGeometry` bleibt einzige Koordinatenquelle.
- In ADR 0003 kurz auf 0004 als optionale Variante verweisen (Status der „späteren
  Variante“ aktualisieren).

### 2. Assets

- Sheet schneiden → `MacGameApp/Resources/Textures/vellidragon/`
- Pflicht: `floor`, `wall`, `goal`, `player`, `crate`
- `crateOnGoal`: nach Sheet-Inspektion — **eigene Kachel bevorzugt**; sonst
  vertraglich Overlay (crate-Sprite über goal-Terrain, ohne ✓-Label)
- Optional: `playerOnGoal` (sonst player auf goal-Terrain reicht)
- Void: kein Sprite → `voidFill`-Farbe
- Notices, SHA, CC0-Lizenztext, Download-Datum (Audio-Vorbild)

### 3. Theme-Schema (V1 additiv)

Strict JSON um erlaubten Block erweitern; unbekannte Keys bleiben verboten.
Beispiel:

```json
"rendering": {
  "profile": "pixelInteger",
  "baseTilePoints": 32,
  "textures": {
    "floor": "Textures/vellidragon/floor.png",
    "wall": "Textures/vellidragon/wall.png",
    "goal": "Textures/vellidragon/goal.png",
    "player": "Textures/vellidragon/player.png",
    "crate": "Textures/vellidragon/crate.png",
    "crateOnGoal": "Textures/vellidragon/crate-on-goal.png"
  }
}
```

- `theme.standard`: kein `rendering`-Block (Default `vectorContinuous`) oder
  explizit `profile: "vectorContinuous"` ohne Textures.
- Farben/Symbole bleiben für UI, Event-Feedback und Vektor-Fallback.
- `StrictThemeJSON`, `ThemeFileV1`, `VisualTheme`, `BuiltInThemes` mitziehen.
- Loader: referenzierte Texture-Dateien müssen im Bundle existieren; sonst Theme
  ungültig → bekannte-ID-Fallback (siehe Vertrag).

### 4. Scale-Profil (`GridGeometry`)

Heute:

```text
tileSize = min(availW / cols, availH / rows)   // stufenlos
```

Pixel (Soll):

```text
continuous = min(availW / cols, availH / rows)
scale      = floor(continuous / baseTilePoints)
tileSize   = scale * baseTilePoints    // nur wenn scale >= 1
```

- `baseTilePoints`: 32 (logische Points, nicht physische Pixel).
- Ziel: Brett **nie größer** als verfügbare Fläche; Letterbox füllt den Rest.
- **Untermaß** (`continuous < baseTilePoints` ⇒ `scale < 1`): kein finaler
  Fallback-Vertrag vorab. Erste Impl. darf pragmatisch sein (z. B. kurz auf
  continuous ausweichen oder `max(1, …)` — beides hat Nachteile).
  **Release-Gate:** manuell kleines Fenster + großes Campaign-Level (~20×17);
  Formel nachjustieren, wenn Overflow, unleserlich oder Vertrag bricht.
- Texturen: `filteringMode = .nearest`; Terrain- **und** Entity-Nodes exakt
  `tileSize × tileSize` (Inset 0).
- Live-Resize: Brett springt in Stufen — erwartet; `duringViewResize` bleibt.
- Unit-Tests: Integer-Vielfache bei `scale >= 1`; Origin punktausgerichtet;
  `tileSize * cols/rows <= available` für den Normalfall.

### 5. Renderer (`SokobanBoardScene`)

| Heute | Pixel-Implikation |
|--------|-------------------|
| `SKSpriteNode(color:)` | Texture laden; Farbe nur Void/Fallback |
| Stroke-Rect | im Pixel-Profil aus |
| Wand/Ziel/Kisten-Symbole | aus; Zustände über Texturen/Overlay |
| Event-Feedback ×/✓ | behalten (`effectLayer`) |
| Push-Pulse über `node.color` | `colorBlendFactor` oder kurzer Overlay-Flash |
| Goal-Pulse / `restoreTerrainColors` | Blend/Alpha oder Ziel-Variante, nicht Fill-Farbe |
| `crateOnGoal`-Label | Texture oder Overlay (Paket 2), kein ✓-Label |
| `entitySize()` ~15 % Inset | Pixel: Inset 0 |
| `apply(theme:)` Rebuild | ok; Profil schaltet Geometry-Formel um |

Layer-Struktur und Revisionsvertrag unverändert.

### 6. Settings / Catalog

- Manifest listet beide Themes; `defaultThemeID` = `theme.standard`.
- Persistierte `themeID`; unbekannte ID → Standard.
- Kaputtes/unvollständiges **bekanntes** Theme (Decode oder fehlende Textur)
  → Built-in-Standard; Catalog bleibt ladbar.
- Theme-Selektor erscheint automatisch bei >1 auswählbarem Theme.

### 7. Tests & Playtest

- Geometry Integer-Scale + Letterbox (`scale >= 1`)
- Theme-Decode mit/ohne `rendering`; unbekannte Keys weiterhin reject
- Scene: nearest, keine Strokes/Brett-Symbole im Pixel-Profil, Feedback sichtbar
- Theme-Switch Standard ↔ Retro inkl. Resize
- **Manuell / Release-Gate:** große Kampagnen-Level + kleines Fenster (Untermaß),
  Reduce Motion, Graustufen (Zustände ohne Symbole lesbar?), Live-Resize-Sprünge,
  Push-/Goal-Feedback spürbar

## Implikationen / Risiken

1. **Letterbox größer** — große Level + kleines Fenster; für Pixel bewusst akzeptiert.
2. **Resize-Ruckeln** — Integer-Stufen statt weiches Mitwachsen.
3. **Feedback-Rewrite** — Push/Celebration hängen an Color-Fills; ohne Anpassung
   kaputt oder unsichtbar.
4. **StrictThemeJSON** — additive Schema-Erweiterung trifft Loader und Theme-Tests.
5. **Pack-Mapping** — `crateOnGoal` erst nach Sheet-Schnitt final (Kachel vs. Overlay).
6. **Untermaß-Skalierung** — bewusst erst im manuellen Pre-Release-Test festnageln.
7. **Accessibility** — VoiceOver-Bretttext unabhängig; visuelle Brett-Symbole weg,
   Event-Symbole bleiben.
8. **Zwei Wartungsstile** — Vektor und Pixel parallel; nur über Profil-Flag verzweigen.
