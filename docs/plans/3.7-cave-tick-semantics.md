## Produktentscheidung (fest aus Architektur + Spez-Tips)

- Wir bauen eine **eigene, deterministische** Höhlenphysik, nicht zuerst einen
  historischen Emulator.
- Original-Cave-Dateien / BDCFF sind Nicht-Ziel (§2.2).
- Deshalb: **simultane Intent-/Double-Buffer-Semantik** als empfohlener Default
  im ADR; In-place-Scan mit `processedGeneration` nur als optionaler späterer
  Kompatibilitätsmodus, falls je gewünscht.
- Explosionen: **sammeln → Konflikte → anwenden → Folge-Queue** (nicht rekursiv
  in-place).
- Gegnerkontakt: **symmetrisch**.
- Rollen: deterministisch, Kandidat **links vor rechts**.
- Tickrate: Kandidat **10 Hz** (`fixedStep = 0.10`); Playtest darf 8–20 Hz
  justieren, Vertrag bleibt fester Schritt.

## Geplante Golden-Konfliktraster (Mindestliste)

Kleine ASCII-Höhlen; erwarteter Endzustand + Event-Reihenfolge bzw. Digest.

| # | Name | Prüft |
| --- | --- | --- |
| 1 | `boulder-falls-into-empty` | Direktfallen, `falling` |
| 2 | `resting-boulder-on-player` | ruhend tötet nicht |
| 3 | `falling-boulder-kills-player` | Einschlag → `dead(at:)` |
| 4 | `player-steps-aside-then-fall` | Freilegen → Fall Folge-Tick |
| 5 | `boulder-push-horizontal` | Schub nur horizontal + freier Raum |
| 6 | `boulder-no-vertical-push` | Vertikal blockiert |
| 7 | `boulder-rolls-left-preferred` | Links vor rechts |
| 8 | `boulder-rolls-right-when-left-blocked` | Alternativseite |
| 9 | `update-once-same-tick` | Objekt nicht zweimal im Tick |
| 10 | `two-intents-same-cell` | Konfliktregel (Explosion > Fall > …) |
| 11 | `exit-opens-at-required` | Öffnen vs. Abschluss nur bei Betreten |
| 12 | `time-expires-kills` | `remainingTicks` → Tod |
| 13 | `ready-no-tick-first-input-is-tick-1` | Ready/Epoche |
| 14 | `explosion-queue-chain` | Queue, nicht Rekursion (kann Stub sein) |
| 15 | `replay-digest-stable` | gleiche Folge → gleicher Digest |

Ergänzend (Timing, oft Session-seitig): Tap innerhalb Tickintervall; Input exakt
auf Grenze; verspäteter Envelope nach Rebase; Catch-up aggregiert eine Revision.
